# 固件方案（草案 v0.1，待确认 T113 板卡与系统后细化）

## 1. 目标
在 T113（全志，双核 Cortex-A7 1.2 GHz + NEON）上实时运行 CIPHER：8 路 PDM 采集 → 每帧位姿 (x, y, ψ) 输出，更新率 ≥ 5–10 Hz。

## 3. 软件流水线（Linux 方案）
```
DMIC(8ch, 48 kHz) ─ALSA─> 环形缓冲 ──> [帧调度: 100 ms 窗口]
   ├─ S1 每基站脉压: 8 路 × 8192 点 FFT + 4 次带内乘法 + IFFT        (NEON FFT, 如 Ne10/kissfft)
   ├─ S2 首径检测 / 噪声底 / 时延域窗口(基带, 6 ms × 8 路)
   ├─ S3 冷启动: TDOA 门控 + 航向瓣搜索（仅初始化/失锁时）
   ├─ S4 跟踪模式: 时延域变量投影 LM（解析 Jacobian）
   └─ 输出: 位姿 + 质量指标(ratio, 残差, 各基站 SNR)
```
- 双核：核 0 采集与脉压，核 1 估计（流水线并行，延迟约 1 帧）。
- 浮点：float32 足够，脉冲插值表和镜像几何预计算。

## 4. 计算量（2026-10-17 实测 Python 剖析 + 估算）

Python 剖析（单帧，跟踪模式）：前端 0.05 s；时延域 LM 2.5 s，其中约 1000 次残差评估（数值 Jacobian：13 参数 × 迭代），单次残差 = 4 基站 × 10 路径 × 8 阵元 × 288 时延样本。

削减验证（`scratchpad bench_reduce.py`，10 个静止位姿）：

| 配置 | 位置 / 航向 | 说明 |
|---|---|---|
| 现状（时延不降采样，10 路径） | 5.35 mm / 0.034° | 基准 |
| **时延降采样 8×**（`FrontEnd(lag_decim=8)`） | **5.06 mm / 0.031°** | 无损（基带仅 1.5 kHz 宽，48 kHz 过采样 30 倍） |
| 降采样 8× + 6 路径 | 6.19 mm / 0.035° | 轻微退化 |
| 降采样 8× + 4 路径 | 22.2 mm / 0.089° | **不可接受** → 镜像至少 6–10 条 |

C/NEON 估算（float32，有效 0.3 GFLOPS/核，降采样 8×、10 路径）：单次残差约 0.6 MFLOP；跟踪模式 5–10 次 LM 迭代 × 解析 Jacobian（约 3–4 次残差当量）→ 每帧 40–80 MFLOP ≈ 0.15–0.3 s/核；4 个基站分两核并行 → **约 0.1–0.15 s/帧，5–10 Hz 可行**。CIPHER-X 第二级（线性最小二乘、整周候选共享投影）< 5 ms。前端（8 通道 × 8 次脉压 FFT）约 20–30 ms。

必须做：解析 Jacobian（变量投影的 Golub–Pereyra 形式）、时延降采样、跟踪模式单次 LM、镜像几何与脉冲插值表预计算。冷启动（含航向搜索与留一门控）约慢 1.5 倍，只在启动/失锁时运行。

## 5. 标定流程（出厂/安装时一次）
1. 用动捕在 10–20 个已知位姿采集 → `calibrate()` 估计每个"基站子带 × 阵元"的复增益 γ（含谐振离散、PDM L/R 采样沿偏移、声孔位置）。
2. 由相干度判别阵元编号手性（PCB 顶/底视不确定的问题）。
3. 写入配置文件，固件启动时加载。

## 6. 开发顺序
1. 采集验证：录 8 通道原始数据，PC 端用 `sim/` 的前端 + 估计器离线跑通（先离线后实时）。
2. C/C++ 移植前端与 LM（以 Python 结果为黄金参考做逐级比对）。
3. 实时化与性能优化。
4. 动捕对比实验。
